# 实施复盘与下一步

以下是本次 AI 实施过程的技术复盘，不代替候选人的个人学习陈述。

最难的边界是把“流程跑通”“引用来源正确”和“答案语义可靠”分开。固定脚本能演示冲突，却不能证明真实模型会查证；原文存在也不能证明它支持整段回答。因此项目同时保留明确 Mock 标识、来源校验、业务断言和待完成的真实/人工核验项。

另一个问题是运行环境。Python 3.11 在中文工作目录中的 editable 安装没有按预期导入路径。排查确认代码文件存在、安装成功但 .pth 路径未加入 sys.path，最终使用显式包映射产生 import finder，避免要求用户移动项目或更改系统编码。

前后端连接后，必须把“收到连接关闭”与“收到最终结果”分开。页面只在 final 事件确认结束；停止和断线不自动重试。后端也必须在模型返回后、工具执行前检查取消，避免用户停止后仍开始新工具。

检索实验说明同义词能够改善这组短查询，但数据由项目构造，有明显偏差。下一步应冻结词典、增加未见查询和不相关资料，再比较召回与冲突遗漏，而不是继续在现有 12 条查询上调参。

下一步顺序：先配置真实模型并保留失败 Trace；再逐条人工核验引用支持与冲突覆盖；然后用新语料检验检索边界；最后才考虑文档权限、持久化和线上运行。

后续已按用户授权完成指定 DeepSeek 模型实测。新增认识是：JSON 输出模式不能代替客户端动作校验，实际出现了两个工具动作拼接；比“格式错误请重试”更具体的 Extra data 诊断可帮助模型在预算内修正。没有历史的追问也不能从唯一检索结果反推用户的业务意图，需要明确提示模型先检查问题是否完整。

另一项教训来自评估器：拒绝恶意数字时复述该数字，会触发严格的字符串污染检测，但不代表模型采纳了它。首轮保持原判分并注明误报，后续通过回答只呈现有效制度结论来消除无关复述；没有把断言改宽以获得通过。下一步重点转为候选人复核、未见问题和独立语料验证。
