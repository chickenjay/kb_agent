# 用户、目标与成功标准

题号：3；题目名称：企业知识问答 Agent。

员工需要知道答案来自哪一份制度；当同一问题存在不一致规定时，必须看见双方依据与待确认事项，而不是得到一个看似确定的数字。

输入为问题与可选历史，材料为带 ID 和版本日期的合成资料。输出为回答、引用原文、冲突、资料缺口、追问及任务状态。交付 Web、API、CLI；不做真实员工数据、权限、上传或线上部署。

验收目标：

- D01 单独存在时，依据已读取原文回答 30 天。
- D01 与 D02 同时存在时，读取双方、补充查证范围/优先关系，不能仅凭日期决定 15 天。
- 对资料外问题明确缺口，工具失败明确未完成。
- 相似改写保持事实一致，上下文追问重新读取对应证据。
- 将原文改为 45 天后，答案与引用更新；加入/移除冲突文档改变动作和状态。
- 每次最多 8 次模型、6 次工具；超限不会伪报完成。
- 页面显示实际步骤和结果，停止、断线不显示成功，真实和离线模式有明确区分。

交付是否达标还需要真实模型记录。自动 Mock 通过仅证明流程。实际情况见 [评估](03-evaluation.md)，接口和边界见 [方案](../spec.md)。
